# 恢复与排错

## 保留哪些本地备份

将完整原 SPI 镜像、SHA256、本机计划文件和原 USB 分区资料保存在自己的离线位置，另放一份在电脑上。完整 SPI 内容可能包含设备身份或厂商配置，不要上传到公开仓库。这里不提供任何一台机器的原始 SPI 镜像。

新发布内核文件时保留旧目录和 `boot.previous.cmd/scr`；Live 入口另保留 `boot-live.cmd/scr`。新内核启动失败，可在 U-Boot 中加载已知可工作的旧脚本，或进入 Live 后恢复文件。不要仅保留指向新内核的唯一一份 boot.scr。

## 常见问题

| 现象 | 排查重点 |
| --- | --- |
| 串口完全无输出 | 供电、3.3 V 电平、独立 DEBUG 口、TX/RX 交叉、端口占用 |
| 串口可见但 FEL 不出现 | 开发板本体 USB-C 的数据线和 WinUSB；CH340 不是 FEL |
| FEL 能查询但不能启动 SPL | 客户端的 H618 支持和匹配 U-Boot，不只是 VID/PID |
| 内核有早期日志但 PID 1 无交互 | UART 依赖加载时序、initramfs 框架识别；不要用 initramfs-tools 的 init 替换 dracut |
| 找不到根文件系统 | UUID、USB PHY/控制器/存储/ext4 模块、供电和 U 盘枚举 |
| Live 启动后数据不保留 | 还没切换到已安装 ext4 根系统，检查 `findmnt /` |
| 连接电脑可以运行，独立供电不启动 | 是否只加载过 RAM U-Boot、SPI 回读、真正冷启动、电源与线材 |
| 重启后时间很旧 | 本板时钟供电条件、NTP，必要时配置 chrony 的时钟恢复；不要在脚本中写死历史时间 |

## SPI 恢复

若 SPI 引导损坏，优先使用 SoC FEL 恢复入口并临时加载可靠 U-Boot。完整恢复原始 SPI 会覆盖整个闪存，只有在核实备份确属这块板、摘要一致、MTD 容量匹配时才进行。恢复操作应参照上游与板厂文档，本项目的 `commit` 是引导器更新工具，不是无条件恢复整片任意镜像的工具。

发布者本次整理项目没有重写现有开发板 SPI，也没有重新分区正在运行的 U 盘。
