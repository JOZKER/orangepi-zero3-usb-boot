# 验证记录与边界

## 原部署的硬件验证

原部署于 2026-10-27 验证：板载 SPI 中的引导器可在断电重新上电后自动从 U 盘进入 Ubuntu；不需要电脑继续加载 FEL 引导代码。U 盘 ext4 上的测试文件在重启后保留。

同次记录确认四个 CPU、SSH 服务、交换文件和串口登录可用，systemd 无失败单元。内核为 `7.3.0-9-generic`。SPI 更新后逐字节回读固件，擦除对齐范围之外的字节与备份一致。

此处不公布 boot ID、UUID、MAC、主机地址、账号或原日志。用简化文字记录硬件结论，不把示例值伪装成原始现场输出。

## 本仓库的重构验证

- 使用原 ISO 在电脑上重新运行文件准备流程，核对 ARM64 Image 与板级 DTB 是否和既有部署输入一致。
- 验证 U-Boot legacy script 的头部 CRC、数据 CRC、长度表及解码结果。
- 验证 initramfs-tools 串口覆盖层、重复调用幂等，以及 dracut 原生 init 保留。
- 验证无效 PE、CPIO、固件摘要和 SPI 回读异常会被拒绝。
- 扫描公开文件及新建提交历史，避免导入部署凭据和设备身份。

通用化后 SPI 的真实写入、空盘重新安装、其他内存规格、其他 ISO、新内核、HDMI 和 Wi-Fi 没有额外硬件覆盖。测试只运行纯函数及文件准备，不在 CI 中接触任何磁盘或闪存设备。

`zero3-verify` 是当前系统的只读检查。它报告 USB 根文件系统等状态，不自动断电，也不证明这次开机一定由 SPI 发起。冷启动须按安装文档实际观察。
